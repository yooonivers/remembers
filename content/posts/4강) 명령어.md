언어
	1. 고급 언어 : 개발자가 이해하기 쉽게
		- 컴파일
			- 소스 코드 -> 목적 코드
			- 오류 발생 시, 전체 코드 중 오류 발생했다고만 앎
		- 인터프리트
			- 인터프리터에 의해 한 줄씩 실행
			- 소스 코드 전체가 저급 언어로 변환되기 까지 기다릴 필요가 없음
			- 오류 발생 시, 발생 시점에 확인 가능

	2. 저급 언어 : 컴퓨터가 실행하기 쉽게
		- 어셈블리어 : 기계어 읽기 편한 상태로 변환

명령어
	1. 구성 
		- 연산 코드
			- 대표 흐름
				- 데이터 전송
					- MOVE
					- STORE
					- LOAD
					- PUSH
					- POP
				- 산술/논리 연산
					- 
				- 제어 흐름 변경
					- 
				- 입출력 제어
					- 
		- 오퍼 랜드
			- 연산에 사용될 데이터
			- 연산에 사용될 데이터가 저장된 위치
				- “주소 필드”라고 말하기도 함
				- 데이터 표현하는데 한계가 있음으로
				- 명령어 주소 지정 빙식
					- 즉시 주소 지정 방식
						- 연산에 사용할 데이터를 오퍼레이터 필드에 직접 명시
						- 가장 간단한 형태의 주소 지정 방식
						- 연산에 사용할 데이터의 크기가 작아질 수 있지만, 빠름
					- 직접 주소 지정 방식
						- 오퍼랜드 필드에 유효 주소 직접적으로 명시
						- 유효 주소를 표햔할 수 있는 크기가 연산 코드만큼 줄어듦
					- 간접 주소 지정 방식
						- 오퍼랜드 필즈네 유효 주소의 주소 명시
						- 앞선 주소 지정 방식들에 비해 속도가 느림
					- 레지스터 주소 지정 방식
						- 연산에 사용할 데이터가 저장된 레지스터 명시
						- 메모리에 접근하는 속보다 레지스터에 접근하는 것이 빠름
					- 레지스터 간접 주소 지정 방식
						- 연산에 사용할 데이터를 메모리에 저장
						- 그 주소를 저장힌 레지스터를 오퍼랜드 필드에 명시

컴퍼일 과정
1. 전처리기
	1. 본격적으로 컴파일 하기 전에 처리할 작업들
	2. 외부 선언된 다양한 소스 코드, 라이브러리 포함 (#include)
	3. 프로그래밍의 편의를 위해 작성된 매크로 변환 (#define)
	4. 컴파일할 영역 명시 (#if 등)
2. 컴파일러
	1. 전처리가 완료되어도 여전히 소스 코드
	2. 전처리가 완료된 소스 코드를 저급 언어로 변환
3. 어셈블러
	1. 어셈블리어를 기계어로 변환
	2. 목적 코드를 포함하는 목적 파일이 됨
4. 링커
	1. 목적 파일은 실행 파일과 다르게 링킹 과정을 거쳐야 함
